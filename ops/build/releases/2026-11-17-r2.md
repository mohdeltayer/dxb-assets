# Release 2026-11-17 r2: faster automatic shot read, footage resolver

Card adv-20261117-server-speed-for-p2, parts A and B (Mohammad: "Build it", 17 Nov 10:36 Dubai). Case: on 17 Nov RPG Maker
was left INCOMPLETE because the automatic shot read took about 13 minutes inside the render step, and Splatoon Raiders
lost a run because its footage address came from a related product on Nintendo's US page. No change to the look, the
templates, the sound or the published post.

## What changes for production

- `"shots": "auto"` (and `[file, "auto", secs, focus]`) reads its footage in about 45 to 60 s per 90 to 120 s trailer on
  4 cores; the whole read is capped at 3 minutes for up to three trailers. qc.json carries `shot_read` (seconds, per file
  and per stage). A trailer with too few clean stretches still fails by name ("add footage"), now in seconds, not minutes.
- prerender.yml mode `shots` uses the same fast read.
- New: prerender.yml mode `footage` with `source` = `steam:<appid>`, a Nintendo US store product page, an IGN video page
  or a playstation.com game page, and `job` = the file stem. It returns each official video as a ready job entry with
  duration, size, fps, bitrate (and the render's low-bitrate flag), the letterbox rows and a full decode check, best
  first, as FOOTAGE_JSON in the log, footage.json in the run summary and as the run's `footage` artifact. Copy a `job`
  entry into the job's "footage" as it is. Nintendo pages give only the product's own gallery (its own nsuid), never a
  related product's video. Any other host is refused.

## Changed paths

- templates/shotpick.py, A: `pick(f, fast=True)` is the fast read: one ffmpeg decode gives the luma and freeze pass, the
  scene cuts and two frames a second at 1280 wide; each frame is read by tesseract once (in parallel); autofocus takes
  the same frames (no seek per sample) and skips scenes under 1.6 s, which can never hold a shot; the smear check runs in
  15 s chunks, alongside; one cropdetect per scene serves the OCR window and the letterbox check. A word read on a fifth
  of the frames in one place is a label on the whole trailer (Forza's "IN-ENGINE FOOTAGE", which both reads catch only on
  some frames): every scene whose 9:16 window covers it is rejected. A per-file budget stops the read; unread frames
  reject their stretch ("not read in time"), so nothing unread is offered. Results are cached per file and size (r1).
  `fast=False` keeps the old read.
- templates/reel.py: `autofocus(..., grab=, cuts=, min_scene=)` (all optional; without them nothing changes): frames from
  a decode already made, the cuts already found, short scenes left at centre; with `grab` the two detectors run at once.
- templates/prerender.py: `luma_parse` split out of `luma_scan` (same result); `ocr_shot(..., read=, bars=)` optional.
- templates/shotgate.py: `_letterbox_rows(..., bars=)` optional.
- templates/autoshots.py: the reader uses the fast read, the cache in shotpick, and the 180 s cap shared between files.
- templates/render_job.py, templates/qc.py: "render_job: shot read:" line; qc.json `shot_read`.
- templates/footage.py (new), B; .github/workflows/prerender.yml: input `source`, mode `footage`, artifact `footage`.
- templates/test_speed.py (new): Nintendo own product only, the source allow-list, the label rule.

## Tests

Local (4 cores): Forza 95 s trailer, old read 237 s, fast 46 to 50 s; RPG Maker 65 s, old 134 s, fast 31 s (2 clean
stretches against 3: the fast read also read text at one stretch's edge); Jedi Survivor 107 s, 54 s (letterboxed, as
before); PUBG 106 s, 47 s, 13 stretches. Unit tests: test_speed, test_autofix, test_onerender, test_onerender_checks,
test_qcfail, test_release2, test_soundcode, test_buildgate, test_fillcheck, test_persongate, test_lifeless: green.
Runner (GitHub, 4 cores):
- speed-rpg-maker-auto (run 1211): read 23 s (old: about 13 minutes); 1 clean stretch for 5 slots, refused by name. The
  trailer is mostly editor UI with text; RPG Maker needs written shot times (as Production 2 did) or a second trailer.
- speed-xbox-3x120-auto (run 1212): three 120 s trailers read in 160 s; seven shots placed; the render then stopped on a
  line too fast to read because one file's budget had counted its decode twice and three shots were shortened. Fixed.
- After the fixes (letterbox boxes from the one decode, budget counted once), run 1214: the same three trailers read in
  111 s (35.8, 33.2, 42.1 s per file); same seven shots; the render stops on the same line reading time, because these
  sale trailers hold only short clean stretches (grounded2's longest free one is 2.4 s). Correct refusal, not a read fault.
- speed-splatoon-auto (run 1215, Production 2's Splatoon Raiders demo job rebuilt from scratch with "shots": "auto" on
  Nintendo's own 192 s gallery video, first 120 s): read and render passed in one dispatch, 3 min 51 s from dispatch to
  the commit (render 153 s); four shots picked by the server (5.14, 49.88, 71.58, 104.04 s), strip checked: clean frames,
  the Inkling face close-up centred, no text in the window.

Resolver: Splatoon Raiders' Nintendo page gives its four own gallery videos (nsuid 70010000122824; the page also carries
related products' videos, none taken), all 1280x720, decode clean; IGN's Ghost of Yotei launch trailer gives the 3840 copy
(letterboxed 1652 rows, low-bitrate flag); Steam 4856440 gives the RPG MAKER U2U Trailer; playstation.com gives the
desktop clip.
