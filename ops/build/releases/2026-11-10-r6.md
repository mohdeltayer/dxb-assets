## Proof (picture quality)

Three weak-source Reels rendered base and hq on the GitHub runner (4 cores), studio/picture-quality, cards/test/pq-*:

| Reel | outro stage (final encode) base -> hq | weak path | file |
|---|---|---|---|
| Dune: Awakening single player | 56.9 -> 67.8 s | 7 shots, deblock, 14.3 s | 30.9 -> 64.7 MB |
| Steam Deck average fps | 47.6 -> 88.0 s | 6 shots, deblock, 17.2 s | 24.7 -> 49.2 MB |
| Switch 2 jailbreak | breaking profile: hq not applied by rule | | |

Frames of three Dune shots from one source copy (base left, hq right): cards/test/pq-dune-shot{30,81,111}-base-vs-hq.png
on studio/picture-quality. On this clean 5.7 Mbps source at 2x, deblock is barely visible. RAISR is not built into the
runner's or the server's ffmpeg, so the upscale step falls back to lanczos ("raisr not installed: deblock only").
Instagram re-encodes to about 5 Mbps, so the slow/16 encode's gain is unlikely to survive upload; it doubles the file.
Recommendation: keep base as the default; use "quality": "hq" on a Reel whose source is flagged lowbit, and decide on
RAISR after a server build of ffmpeg with the raisr filter.

## Parallel runners (I)

Today one runner instance on dxb-render-1 takes one job at a time. With this release the shared caches are safe for two
jobs at once (the picture-pass cache and end-card master write per-process temp files and replace atomically; uploads
and temp folders are per job). Memory peaks at about 1.5 GB of 16 GB per render. A second instance needs, as root on
the server (registration token from the repo's Settings, Actions, Runners, New runner; never pasted anywhere):

    sudo -u runner bash -lc 'mkdir -p ~/actions-runner-2 && cd ~/actions-runner-2 && tar xzf ~/actions-runner/actions-runner-linux-x64-*.tar.gz && ./config.sh --url https://github.com/mohdeltayer/dxb-assets --token <TOKEN> --name dxb-render-1b --labels dxb-render --work _work --unattended'
    cd /home/runner/actions-runner-2 && sudo ./svc.sh install runner && sudo ./svc.sh start

(The path to the runner tarball and the service user are as installed by the server's runner setup; check them first.)
